# Professor Maker

한 사람의 연구자, 여덟 번의 봄. 교수의 입장에서 한 명의 학생을 지도하고 연구실을 운영하는 한국어 경영·육성 시뮬레이션입니다.

[플레이하기](https://gahyoun.github.io/professor-maker/)

교수의 성별·연령·연구 분야·학교 유형을 선택하고, 매달 면담에서 학생이 제안한 월별 4–5주의 일정을 조정합니다. 학부연구생에서 석사·박사 또는 석박사통합과정으로 이어지며, 연구성과와 관계에 따라 진로와 후일담이 달라집니다. 지도 종료 기록을 제외한 후일담에서는 함께한 연구와 추억을 CV로 보관할 수 있습니다.

웹과 모바일을 지원하며 첫 방문 후 오프라인에서도 플레이할 수 있습니다. 저장 데이터는 사용하는 브라우저에 남고, JSON 파일로 내보내 다른 기기로 옮길 수 있습니다. 현재 한국어판이며 영어판은 추후 확장합니다.

졸업 이후에는 가상 연구성과와 h-index, 전체 파라미터 그래프를 확인하고 워터마크가 있는 CV를 인쇄·PDF로 보관할 수 있습니다. 외부 대학원 진학을 응원하면 함께한 기간의 기록으로 마무리합니다.

학생 이름과 성별은 자동 배정됩니다. 학부 시기에는 학회에서 현장을 배우고, 마지막 학년 10월의 학부생 대회에서 첫 발표를 준비합니다.

대학원부터 7월·1월에 해외학회 초록을 투고합니다. 연구 준비도와 운에 따라 다음 달 채택 결과가 도착하며, 연구비가 충분하면 8월·2월에 발표와 교류를 위해 학생을 보낼 수 있습니다.

모바일에서는 상단의 도트 랩뷰를 보면서 아래 선택지를 스크롤해 조정합니다. 일정 확정 뒤 같은 연구실에서 주별 활동이 이어지고, 학회·휴식·학위심사에는 장소가 바뀝니다. Wet lab의 자재는 운영비와 연구환경 예산에 따라 달라집니다.

주별 활동은 문헌·교과목 공부, 데이터 분석, 실험 또는 계산·모델링, 언어·발표 연습, 산학과제 RA, 수업보조 TA와 자율 시간입니다. 교과목 공부는 시험·퀄 준비에 도움이 되고, 학회 발표 전 연습도 필요합니다. 자율 시간에는 학생이 공부·여행·휴식을 선택합니다. 면담과 안부 확인은 교수의 별도 활동입니다.

교수 업무는 크레딧 블록을 클릭·터치해서 배분하며, 남긴 크레딧이 있어도 진행할 수 있습니다. 예산은 증감 버튼으로 조정합니다. 연간 일정은 실제 달력에 가까운 52–53주이며, 학부 시험기간·학회 주간과 단계별 학위심사 이야기가 이어집니다.

논문 심사는 [대학의 공개 심사 절차 안내](https://professor.skku.edu/cse/notice_grad.do?articleNo=216421&attachNo=189671&mode=download)를 참고해 초안·발표·질의응답·수정·최종 판정으로 단순화했습니다. 실제 학교와 전공별 절차는 다를 수 있습니다.

## 개발

Node.js 24 이상으로 테스트합니다. 별도 npm 패키지는 필요하지 않습니다.

```sh
npm test
python3 -m http.server 4173 --directory dist
```

브라우저 검증은 Playwright가 설치된 환경에서 `PLAYWRIGHT_MODULE`을 지정하고 `node tests/browser-smoke.mjs`를 실행합니다.

`main`에 반영하면 GitHub Actions가 테스트 후 `dist`를 Pages에 배포합니다. 릴리스는 의미적 버전과 Git 태그로 구분하며 변경 내역은 [CHANGELOG](CHANGELOG.md)에 기록합니다. 저장 형식 버전과 배포 버전은 별도로 관리합니다.

운영자용 밸런스 문서와 아키텍처, 제공받은 원본 연구 데이터는 공개 게임 배포에 포함하지 않습니다.

## 익명 기록과 관리자 서버

분석 기록은 선택 동의가 있어야 저장되며 실제 이름·연락처를 포함하지 않습니다. 공개 Pages에서는 IndexedDB에 보관하고 플레이어가 익명 JSON을 직접 내보냅니다. 서버는 제작자 전용 비공개이며 관리자 로그인·접근키로 보호된 화면에서 이 파일을 DB에 가져올 수 있습니다. 공개 플레이어의 기록이 비공개 서버로 자동 전달되지는 않습니다.

서버는 SQLite 기반 D1을 사용합니다. 런별 토큰, 월별 고유 키, 엄격한 입력 범위, 중복 갱신, 요청 크기 제한, 삭제 API를 적용합니다. 서버 기록은 90일 뒤 분석 대상에서 제외하고 이후 신규 등록·관리자 요청에서 만료 데이터를 순차 삭제합니다. 저장 데이터는 최대 50,000런, 관리자 내보내기는 요청당 최대 20,000행입니다.

`npm run build:hosted`로 전용 Worker를 구성합니다. GitHub Pages는 `dist`의 정적 게임을 사용하고 Sites는 `.openai/hosting.json`의 기존 비공개 프로젝트와 D1을 사용합니다. 관리키는 Sites의 비밀 환경 변수 `ADMIN_KEY`로만 주입합니다.

## 제작 및 참고

제작자: 김가현. 가상의 STEM 연구실을 소재로 한 독립 창작 게임입니다. 제작자의 [GitHub 저장소 디렉토리](https://github.com/Gahyoun?tab=repositories). 경상국립대학교 홈페이지의 색상과 서체 구성을 참고하며 학교 로고는 사용하지 않습니다.

시간과 선택의 흐름은 [80억 분의 1](https://1in8b.life/ko/), 연구 진행과 사건 구조는 [PhD Simulator](https://research.wmz.ninja/projects/phd/index.html)와 [phd-game](https://github.com/morriswmz/phd-game)을 참고했습니다. [NEEDY STREAMER OVERLOAD](https://store.steampowered.com/app/1451940/)의 관계 관리·선택·여러 후일담이라는 구성도 참고합니다. 참고 게임의 코드와 대사는 복사하지 않았습니다. 학위 목표와 경영 효과는 게임 규칙이며 실제 대학의 공통 규정이 아닙니다. 과제 수 제한은 [한국연구재단 안내](https://webzine.nrf.re.kr/magazine/2604/sub1.php), 인건비 계정은 [경상국립대 산학협력단 안내](https://www.gnu.ac.kr/research/cm/cntnts/cntntsView.do?cntntsId=3988&mi=7451)를 바탕으로 단순화했습니다. 실제 사업의 예외·기간·집행 규정은 게임과 다릅니다. h-index는 [Hirsch의 정의](https://arxiv.org/abs/physics/0508025)에 따라 논문별 인용 수로 계산하며 인용 증가와 진학 기준은 가상의 게임 모델입니다.

진로·취업 상태·학위과정의 중단은 인물의 가치나 건강 상태에 대한 평가를 뜻하지 않습니다.
