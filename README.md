# Professor Maker

교수의 입장에서 한 명의 학생을 지도하고 연구실을 운영하는 경영·육성 시뮬레이션입니다. 한국어판과 북미 배경의 영어판을 제공합니다.

[플레이하기](https://gahyoun.github.io/professor-maker/)

교수의 성별·연령·연구 분야·학교 유형을 선택하고, 매달 면담에서 학생이 제안한 월별 4–5주의 일정을 조정합니다. 학부연구생에서 석사·박사 또는 석박사통합과정으로 이어지며, 연구성과와 관계에 따라 진로와 후일담이 달라집니다. 지도 종료 기록을 제외한 후일담에서는 함께한 연구와 추억을 CV로 보관할 수 있습니다.

새 게임에서 `신임교수(쉬움)`과 `현실(보통)`을 선택합니다. 쉬움은 시작 연구비를 최소 8,000만원으로 배정하고, 첫 24개월에 필수 인건비·운영비의 부족액만 월 최대 300만원, 회차 총 3,000만원까지 보전합니다. 현실 모드도 첫 24개월에 같은 필수 비용의 부족액을 월 최대 150만원, 회차 총 1,500만원까지 지원합니다. 선택 지출과 역량 성장에는 추가 보상이 없습니다. 이전 저장의 난이도는 현실 모드로 이어지며, 이미 지난 달의 지원금을 소급해 지급하지 않습니다. 두 모드 모두 향후 과제 지원액을 약 15% 늘립니다. 금액과 기간은 한국어판의 가상 게임 규칙입니다.

연구비가 부족해도 유효한 계획의 월 진행은 막히지 않습니다. 부족액을 학과에서 자동 차입하고, 학생인건비 풀은 급여에만 사용합니다. 미상환 차입금에는 월 0.25% 이자와 작은 학교행정 부담이 생기며, 이후 과제 입금의 운영비 몫으로 상환합니다. 미상환액이 1,000만원을 넘고 새 차입이 3개월 연속 이어지면 경고와 회복 기한을 거쳐 종료합니다. 교수 업무도 같은 업무가 0인 상태를 3개월 연속 회복하지 못하면 원인을 남기고 종료합니다. 필수 비용 부족 시 선택할 수 있는 운영 보류는 연구·급여 실적 없이 달력과 기존 과제의 입금을 진행합니다.

온보딩에서 버전별 업데이트 플로팅 박스로 점검·보수·밸런스 변경을 안내하며 닫은 뒤에도 다시 볼 수 있습니다. 첫 회차에는 플로팅 박스로 목표와 콘텐츠를 소개한 뒤 메뉴·주간 일정·업무·예산·연구비 신청·수행 보고를 실제 화면에서 안내합니다. 건너뛰기와 재시작을 지원하며 안내 진행은 게임 저장과 별도로 보관합니다. 전공 지식보다 학생의 대사와 수행 보고를 읽고 계획을 조정하는 게임입니다.

웹과 모바일을 지원하며 첫 방문 후 오프라인에서도 플레이할 수 있습니다. 진행과 후일담은 사용하는 브라우저에 남고, JSON 파일로 내보내 다른 기기로 옮길 수 있습니다. [북미 영어판](https://gahyoun.github.io/professor-maker/en.html)은 9월 학기 시작과 현지 교육·연구 환경을 반영하며 한국어판과 별도로 저장합니다. 저장 위치와 선택 분석 기록의 전송 방식은 아래에 설명합니다.

졸업 이후에는 가상 연구성과와 h-index, 전체 파라미터 그래프를 확인하고 워터마크가 있는 CV를 인쇄·PDF로 보관할 수 있습니다. 외부 대학원 진학을 응원하면 함께한 기간의 기록으로 마무리합니다.

새 회차는 입학 면접에서 후보 3명 중 한 명을 선택합니다. 학점·관심 분야·면접 인상만 확인하며 성실도·스트레스 내성은 숨깁니다. 후보는 다시 뽑지 않으며 선택 후 같은 회차에서는 교체할 수 없고 지도 종료 뒤 새 입학면접을 엽니다. 공유 코드로 같은 학생을 재현할 수 있고, 기존 저장의 학생은 유지합니다. 학부 시기에는 학회에서 현장을 배우고, 마지막 학년 10월의 학부생 대회에서 첫 발표를 준비합니다.

대학원부터 7월·1월에 해외학회 초록을 투고합니다. 연구 준비도와 운에 따라 다음 달 채택 결과가 도착하며, 8월·2월에 발표와 교류를 위해 학생을 보낼 수 있습니다. 비용은 운영비와 필요 시 자동 차입으로 충당합니다.

모바일에서는 상단의 도트 랩뷰를 보면서 아래 선택지를 스크롤해 조정합니다. 일정 확정 뒤 같은 연구실에서 주별 활동이 이어지고, 학회·휴식·학위심사에는 장소가 바뀝니다. Wet lab의 자재는 운영비와 연구환경 예산에 따라 달라집니다.

생명·화학·물리·건축·계산 연구실에 맞는 장비와 테이블을 배치합니다. 문헌 공부·분석은 의자에 앉아서, Wet 실험은 해당 분야의 기구를 다루며 진행합니다. 회복 장면은 산·바다·도시·침대와 세 가지 색 조합으로 표현합니다.

수업보조 TA는 칠판 앞에서 개념 도표를 가리키고 설명하는 장면으로 표현합니다. 칠판 종류별 판서가 순서대로 나타나며, 동작 줄이기 설정에서는 정지 장면으로 표시합니다.

주별 활동은 문헌·교과목 공부, 데이터 분석, 실험 또는 계산·모델링, 어학, 발표 연습, 산학과제 RA, 수업보조 TA와 자율 시간입니다. 교과목 공부는 시험·퀄 준비에 도움이 되고, 학회 발표 전 연습도 필요합니다. 자율 시간에는 학생이 공부·연구·여행·휴식을 선택합니다. 면담과 안부 확인은 교수의 별도 활동입니다. 스트레스가 높고 체력 또는 정신력이 낮으면 학생이 1–2주 회복을 요청합니다. 월 진행 전에 허락·거절을 결정하고, 허락하면 고정 일정 외에 회복 시간을 확보하며 라포가 오릅니다. 거절하면 기존 연구 계획을 이어가되 스트레스가 오릅니다. 몸이나 마음이 한계에 도달하면 경고와 원인을 기록하고 일부 활동을 멈춰 회복합니다.

학생은 진로 고민, 수업·퀄 준비, 예상과 다른 결과, 독립 연구 등을 면담에서 먼저 꺼냅니다. 관계가 아직 충분히 쌓이지 않았을 때는 질문을 망설이는 대사와 관찰이 나타납니다. 답변에 따라 다음 면담 대사와 후일담의 추억이 달라집니다. 라포와 신뢰는 하나의 관계 파라미터로 관리하며 진행 중에는 대사로 추론합니다. 라포와 학습·연구·어학·소통 등 역량은 50부터 긍정적 변화가 점점 작아지는 지수 포화 모델을 사용합니다. v4.14부터 축적되는 역량의 상승량은 종전의 절반이며, 월간 학습 정책은 실제 주별 연습보다 적은 보상을 줍니다. 실험·분석의 학술 역량 보상도 성과에 따라 다릅니다. 감소와 체력·의욕의 회복은 별도로 계산합니다.

새 학생을 만날 때마다 교수 프로필을 정합니다. 교수 호칭은 기본값 또는 성씨 직접 입력을 선택할 수 있으며, 학생 이름·성별은 설정할 수 없습니다. 연구 피드백은 가로로 긴 선택지를 세로로 쌓아 터치하기 쉽게 구성합니다.

해외 연구년 중에는 교수 단독·교수 동반 국내학회 참석을 선택할 수 없고, 학생 단독·불참만 가능합니다. 귀국 후 선택이 복원됩니다. 국내학회는 1인당 20만원, 해외학회는 1인당 400만원을 사용합니다. 안 가기·교수 혼자·교수와 학생·학생만 참석을 선택하며, 교수만 참석하면 학생의 일정과 학술발표 실적은 유지됩니다. 해외 학생 발표에는 채택된 초록이 필요합니다. 경비는 운영비에서 지급하고 학생인건비 풀링 계정으로 충당하지 않습니다.

논문과 학회에는 가상 IF와 A/B/C 티어가 있습니다. 더 도전적인 목표에는 더 많은 연구·발표 준비가 필요하며, 심사 결과와 기록에 반영됩니다. 실제 학술지의 수치나 평가를 나타내지 않습니다.

교수 업무는 크레딧 블록을 클릭·터치해서 배분하며, 남긴 크레딧이 있어도 진행할 수 있습니다. 월별 한도는 연령·학기·방학·연구년과 일정에 따라 8–10크레딧입니다. 기존 저장의 배분이 현재 한도를 넘으면 불러올 때 조정합니다. 예산은 증감 버튼으로 조정합니다. 연간 일정은 실제 달력에 가까운 52–53주이며, 학부 시험기간·학회 주간과 단계별 학위심사 이야기가 이어집니다.

논문 심사는 [대학의 공개 심사 절차 안내](https://professor.skku.edu/cse/notice_grad.do?articleNo=216421&attachNo=189671&mode=download)를 참고해 초안·발표·질의응답·수정·최종 판정으로 단순화했습니다. 실제 학교와 전공별 절차는 다를 수 있습니다.

매년 3월에 학생인건비 계상률을 정합니다. 초기 총 연구비는 저장된 시드에 따라 3,000만원–2억원을 1,000만원 단위로 배정하며, 국립대·사립대는 운영비와 학생인건비 풀링을 분리합니다. 게임의 과제 공모는 3월·9월에만 열리고 과제는 2–5년간 지원합니다. 후속 과제에는 마감 전 신청과 경쟁 심사가 필요하며 책임 3개·전체 5개 제한을 적용합니다. 미선정 시 교내 공백지원은 한 회차에 1년만 지급합니다. Wet lab은 소모품·실험 운영비가 더 높고 과제의 연간 지원 규모도 dry lab의 1.5배로 설정합니다. 과학기술원은 연간 지원이 더 넉넉한 학교 유형이며 시작 난이도와 별도로 선택합니다. 이전 재정 규칙의 저장 파일을 불러오면 운영비·풀링 합계가 2억원을 초과하는 경우 한 번만 비례 조정하고 원래 숫자를 이관 기록에 보관합니다. 새 규칙에서 정상적으로 쌓인 잔액을 반복해 줄이거나 초기 자금을 다시 입금하지 않습니다.

매달 기존 일정·상담 이슈가 없는 달에도 연구 범위·검증·업무량·자원 예약·세미나·초고에 대한 운영 선택이 생깁니다. 선택 전에는 비용과 장단점을 문장으로 확인하며, 학생의 준비와 관계에 따라 위임의 결과가 달라집니다. 학생의 실제 반응은 연구실 기록에 남습니다. 과제 선정·미선정과 수상 뒤에도 계획 유지·직접 지원·범위 조정 중 대응을 고릅니다. 선정과 입금은 과제명·추가 연구비를 담은 “좋은 소식”으로 알리고, 예정된 연차 입금과 신규 선정을 구분합니다. 총 입금액과 차입 상환액을 따로 표시합니다. 기존 저장의 과거 잔액·입금 기록은 유지하고 향후 지급분부터 증액합니다.

학회 참석은 한 달 전에 의논하며, 과제 선정·탈락과 학술발표 수상은 이번 달 이슈로 확인합니다. 연구년은 3–7년차 중 한 번 발생합니다. 연구 실패가 이어지면 별도의 면담이 열리고, 학생의 제안을 존중한 정도와 반복적인 무응답도 관계에 반영됩니다.

메일은 직업·관계·실제 경험에 더해 기질, 종료 시점의 상태와 연구 분야를 조합합니다. 자동 구문은 close 최대 2개·reserved 최대 1개이며 distant·휴학·중단·운영 종료·미완·유튜버에는 붙이지 않습니다. 연구실 유형에 맞는 회상만 고르며, 교내 연구원에게도 신입 구문은 붙이지 않습니다. 요청 앞에만 배치하고, 수집한 문장 ID를 보관해 미노출 구문을 우선 선택합니다. 선택은 편지마다 고정되며 JSON 저장에도 함께 담깁니다. 엔딩 기록은 첫 장의 CV 요약과, 다음 장부터 이어지는 학술 보고서 형식의 파라미터 그림·활동 부록으로 구성됩니다. 160열 출력 그리드와 3.5등신 비율의 학생 도트와 앞머리 16종, 연구실 명암과 소품, 학회장 4종은 직접 제작한 그래픽입니다.

공모의 구성은 [NRF의 공개 사업 안내](https://webzine.nrf.re.kr/magazine/2511/sub1.php)와 [2026년 9월 공고 목록](https://webzine.nrf.re.kr/e-alim/alim_396/index.php)을 참고했습니다. 실제 접수 시기는 사업마다 다릅니다. 게임의 3·9월 공모, 지원 금액과 선정 확률은 현실 통계나 현행 제도를 나타내지 않는 게임 규칙입니다.

## 개발

Node.js 24 이상으로 테스트합니다. 별도 npm 패키지는 필요하지 않습니다.

```sh
npm test
python3 -m http.server 4173 --directory dist
```

브라우저 검증은 Playwright가 설치된 환경에서 `PLAYWRIGHT_MODULE`을 지정하고 `node tests/browser-smoke.mjs`를 실행합니다. `tests/mobile-lab-smoke.mjs`는 랩뷰 스크롤과 주별 연출, `tests/counseling-ui-smoke.mjs`는 상담·성씨·참석 선택의 실제 클릭을 확인합니다.

`main`에 반영하면 GitHub Actions가 테스트 후 `dist`를 Pages에 배포합니다. 릴리스는 의미적 버전과 Git 태그로 구분하며 변경 내역은 [CHANGELOG](CHANGELOG.md)에 기록합니다. 저장 형식 버전과 배포 버전은 별도로 관리합니다.

운영자용 밸런스 문서와 아키텍처, 제공받은 원본 연구 데이터는 공개 게임 배포에 포함하지 않습니다. 연구 제목은 김가현이 제공한 NRF 자료 분류·패러프레이징 파일에서 추출한 1,343개 제목을 분야별로 사용합니다. 파일에 명시된 원자료는 [2023–2025년 일부 신규 선정 과제](https://www.data.go.kr/data/3049029/fileData.do)이며 분야는 제공된 추정 분류입니다. 전체 NRF 과제를 대표하는 통계가 아닙니다. 원제·기관명·원본 워크북은 게임에 포함하지 않습니다.

## 게임 저장과 선택 분석 기록

**GitHub Pages판은 기기에만 저장합니다. 공식 Sites판도 게임 진행은 기기에 저장하며, 사용자가 동의한 분석 기록만 서버로 전송합니다.** 분석 동의는 선택 사항이며, 동의하지 않아도 게임을 플레이하고 저장할 수 있습니다.

| 데이터 | GitHub Pages판 | 공식 Sites판 |
| --- | --- | --- |
| 현재 진행·학생·수집한 후일담 | 사용자 브라우저 | 사용자 브라우저 |
| 월별 저장점·수동 저장점 | 사용자 브라우저의 IndexedDB | 사용자 브라우저의 IndexedDB |
| 동의한 익명 분석 기록 | 사용자 브라우저의 IndexedDB에만 저장. 자동 전송 없음 | 사용자 브라우저의 IndexedDB에 저장한 뒤 제작자의 Cloudflare D1으로 전송 |

한국어판의 현재 진행·후일담은 `localStorage`에 저장합니다. 영어판은 별도의 IndexedDB에 저장하며, IndexedDB를 사용할 수 없을 때는 영어판 전용 `localStorage`를 사용합니다. 한국어·영어판은 진행·저장점·분석 동의를 서로 분리합니다. GitHub Pages와 Sites는 주소가 달라 브라우저 저장도 공유하지 않습니다. **클라우드 세이브와 기기 간 자동 동기화는 없습니다.** 주소나 기기를 옮길 때는 게임의 JSON 내보내기·불러오기를 이용합니다. 브라우저 데이터를 지우면 기기 저장도 삭제되므로 필요한 진행은 파일로 보관해 주세요.

공식 Sites판은 [professor-maker.gahyoun.chatgpt.site](https://professor-maker.gahyoun.chatgpt.site/)입니다. 분석 기록에는 무작위 실행 ID, **판 구분 `edition: "ko"`(한국판) / `"en"`(북미판)**, 전공·학교 유형·연구 방식, 월별 선택·게임 수치·성과·엔딩이 포함되며 이름·연락처는 포함하지 않습니다. 판 구분은 브라우저 언어나 학생의 이름으로 추정하지 않고 실행 프로필에 저장합니다. 서버 집계와 JSON 내보내기에도 같은 값을 사용하며, 판 구분이 없거나 유효하지 않은 새 서버 기록은 거부합니다. 게임 저장 전체나 후일담 원문을 클라우드 세이브로 올리지 않습니다. **익명 데이터가 연구 협력자와 공유될 수 있음**을 동의 안내에 명시합니다. 공유 대상은 Sites 서버로 전송되거나 유저가 제작자에게 직접 제공한 익명 데이터이며, GitHub·로컬 기기에만 남은 기록은 자동으로 공유되지 않습니다. GitHub Pages판의 분석 JSON 내보내기는 기기에 파일을 내려받는 기능으로, 내보내기만으로 제작자에게 전달되지 않습니다.

v4.22.0부터 새 동의를 받은 서버 분석 기록은 실행 등록일로부터 **최대 5년** 보관하며 분석 목적이 끝나면 더 일찍 삭제합니다. 이전 90일 정책의 동의는 새 정책으로 연장하지 않습니다. 동의를 기본 해제 상태로 바꾸고 해당 판의 기존 기기 분석 기록을 폐기하며, 서버에서도 이전 정책의 기록을 정리합니다. 게임 진행·후일담·저장점은 유지합니다. 새 분석 JSON 형식은 `professor-maker-anonymous-v2`, 동의 정책은 `anonymous-gameplay-five-years-v2`입니다. 이전 정책의 파일은 새 정책으로 가져오지 않습니다.

설정에서 분석 동의를 철회하면 이후 분석 기록 저장·전송을 중단하고 해당 언어판의 기기 분석 기록을 지웁니다. Sites판은 기기에 보관된 실행별 삭제 토큰으로 해당 서버 기록의 삭제도 요청합니다. 월별 업로드 권한은 등록 후 90일 동안 유효하며, **토큰의 업로드 권한 만료와 5년 보관 만료는 별개**입니다. 업로드 권한이 만료되어도 해당 토큰으로 보관 중인 기록을 삭제할 수 있습니다. 토큰을 갱신해 새 서버 실행을 등록할 때 이전 실행의 삭제 토큰도 보관합니다. 서버 삭제가 실패하면 다시 시도하라는 안내를 표시합니다. 기기 저장을 이미 지워 삭제 토큰까지 없어진 경우에는 기기에서 해당 서버 기록의 삭제를 요청할 수 없습니다.

보관 만료일에는 서버 기록을 분석 대상에서 제외하고 **매일 새벽 3시(Asia/Seoul) 클라우드 예약 작업으로 만료 행을 삭제**합니다. 사이트 방문·게임 API 요청이나 사용자의 컴퓨터가 켜져 있을 필요가 없습니다. 실제 행 삭제는 다음 일일 정리 때 수행되므로 정상 실행 시 만료 후 최대 24시간의 정리 지연이 있을 수 있습니다. 실패하면 재시도하며, 계속 실패하면 운영자에게 알립니다. 기존 요청 시 정리도 유지합니다. 관리자 정책 정리 API는 이전 정책·만료 기록을 폐기하며, 분석 목적 완료 시 현재 기록의 조기 삭제도 지원합니다.

예약 작업은 소유자 전용 실행 경로를 사용하고, 공개 게임의 `RETENTION_MAINTENANCE_KEY`로 보호한 만료 정리 API에만 접근합니다. 이 키는 분석 열람·내보내기·가져오기·정상 보관 데이터의 조기 전체 삭제 권한이 없습니다. 한 배치에 최대 500개 실행과 해당 월별 행을 트랜잭션으로 삭제하며 완료할 때까지 반복합니다. 응답·로그에는 시간·삭제 건수·남은 만료 건수만 기록합니다. 비밀키나 서비스 접근 토큰은 저장소·브라우저·예약 프롬프트에 넣지 않습니다. [자동 정리 운영 절차](docs/analytics-retention-schedule.md)를 제공합니다.

GitHub 저장소에는 게임 코드, 분석 API 코드와 [테이블 생성 SQL](drizzle/0000_game_analytics.sql), [보관 정책·판 구분 추가 SQL](drizzle/0001_analytics_retention_policy.sql)이 올라갑니다. **실제 플레이어 기록과 실행 중인 D1 DB는 GitHub에 저장하지 않습니다.** D1은 SQLite 기반이며 `game_runs`에 실행 정보와 `edition`·`consent_version`·`retention_until`을, `game_months`에 월별 분석 JSON을 보관합니다. 실행별 토큰, 월별 고유 키, 입력 범위 검증, 중복 갱신, 요청 크기 제한, 삭제 API를 적용합니다. 유효한 서버 실행은 최대 50,000개, 관리자 내보내기는 요청당 최대 20,000행입니다.

`npm run build:hosted`로 Sites용 Worker를 구성합니다. GitHub Pages는 `dist`의 정적 게임을 사용하고, 공식 Sites판은 `.openai/hosting.json`의 공개 게임 프로젝트와 D1을 사용합니다. 분석 수집 API와 관리자 API를 구분하며, 관리자 가져오기·요약·내보내기 API는 비밀 환경 변수 `ADMIN_KEY`로 보호합니다. 관리키는 클라이언트 코드나 공개 저장소에 포함하지 않습니다.

진로·취업 상태·학위과정의 중단은 인물의 가치나 건강 상태에 대한 평가를 뜻하지 않습니다.
